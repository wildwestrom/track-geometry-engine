# Code review checklist

Line counts are for `track_geometry/content/track_geometry/*.script.tl` (7,405 lines in all).
Read bottom-up: each layer depends only on the ones above it, so you never meet a call to something you haven't read yet.

## 0. Orientation

- [ ] Know that this is **Teal**, not Lua. Teal is typed Lua that compiles to Lua, so `local x: number`, `record`, `enum` and `as` casts are Teal, not Lua. Skim the Teal tutorial (https://github.com/teal-language/tl/blob/master/docs/tutorial.md) first.
- [ ] `AGENTS.md`: the workflow (`agent-scripts/ship` = `check.sh`, then `sync.sh`)
- [ ] `NOTES.md`: game API facts and gotchas found in game. Skim it now and reread the relevant section before each module that touches the game.
- [ ] `track_geometry/mod.json` and `_metadata/modinfo.json`: mod id `track_geometry_tool`, no dependencies
- [ ] `content/mod.script.tl`: an empty stub (3 lines)
- [ ] `content/track_geometry/tg_menu.res.lua`: registers the "Track Geometry" row in the game's track builder. It points at `tg_gui.script@TgMenuPlugin`.
- [ ] `content/track_geometry/tg_probe.res.lua`: registers the `TgProbe` plugin in the bottom game bar
- [ ] `content/track_geometry/tg_gui.css.lua`: styles (22 lines)
- [ ] `tlconfig.lua`, `check.sh`, `sync.sh`, `all_def.tl`: build and type-check setup. The `.tlpath` symlink trick maps `track_geometry_tool::/…` requires to files.
- [ ] Windows variants (`check.ps1`, `sync.ps1`, `tfpaths.ps1`): skip unless you use Windows
- [ ] `agent-scripts/`: AI helper scripts, not mod code. Skim `README.md` only.
- [ ] `thumbnail/`, `svg2tga`, `track_curve_icon.svg`, `_metadata/`, `strings.json`, `texture_metadata_cache.lua`: assets and packaging

## 1. Structure at a glance

Layers, from the bottom (each uses only the layers above it in this list):

```
1. geometry                       path maths, no deps
2. alignment, profile, ends       sampling, vertical profile, picked ends
3. structures, crossings, readout bridges/tunnels, crossings, tooltip text
4. edit                           PIs and curve sizes being edited
5. layout, plan                   path -> native game proposal
6. world                          reads the game world (game API)
7. session, proposal, gizmos      tool state, ghost lifecycle, shapes to draw
8. gui                            wires everything to the game (game API)
```

(Simplified: a few modules also reach a layer or two down. Check each file's `require` lines.)

Pure modules (no game API, tested offline in `test/`): everything except `world` and `gui`.

Data flow: the player picks two ends (`session`), then edits PIs (`edit`). `plan` builds the path (`geometry`, `alignment`, `profile`), classifies bridges and tunnels (`structures`) and finds crossings (`crossings`). `layout` turns that into a native game proposal. `proposal` manages the ghost's lifecycle. `gizmos` and `readout` describe what to draw. `gui` wires it all to the game.

## 2. Pure maths layer (no game API)

- [ ] **`tg_geometry`** (483 lines): the core. A port of the Lean spec, with straights, arcs and transition spirals. Check it against `test/geometry_test.lua` and `test/fixtures.lua`. Fixtures are generated by `lake exe fixtures` from the Lean code, which lives outside `mod/`.
- [ ] **`tg_alignment`** (150): samples a path into nodes, each with a position and heading. Look at the Hermite tangent length and the `step`/`maxTurn` limits.
- [ ] **`tg_profile`** (121): vertical profile, a monotone cubic (PCHIP-like) through elevation points
- [ ] **`tg_ends`** (490): turns a picked end (free track end, node, point along a piece, ground) into a point and a direction, and builds the starting alignment between two ends
- [ ] **`tg_structures`** (155): classifies pieces as bridge, tunnel or ground, using thresholds copied from the game, and tidies short runs
- [ ] **`tg_crossings`** (289): finds where new track crosses existing streets or track, so they can share a node. Mostly intersection geometry, so a likely place for edge-case bugs.
- [ ] **`tg_readout`** (240): tooltip lines and the badge at each curve (speed, grade)

## 3. Editing and planning

- [ ] **`tg_edit`** (841): the edit model. Turns (PIs), curve size brackets, and the move/add/remove rules with their constraints at ends that have a heading. Large, so read it in two sittings.
- [ ] **`tg_layout`** (475): builds the native proposal, with edges numbered `-1..-m` and nodes `-(m+1)..`. Handles switches, which replace the pieces at a node, and cuts. Read the NOTES.md section "Building track (proposals)" first.
- [ ] **`tg_plan`** (209): the glue. It makes a `dense` path (for reading the ground) and a `built` path (the pieces handed to the game).

## 4. State machines

- [ ] **`tg_session`** (706): the tool's step (pick start, pick end, edit), the click/right-click/back meanings, and the events the GUI feeds in. The GUI reads its fields and never writes them, so check that this holds.
- [ ] **`tg_proposal`** (638): the ghost lifecycle: when to remake it, the game's check results, rounds that clear town buildings, and the build gate
- [ ] **`tg_gizmos`** (223): the shapes to draw (circles, brackets, polylines), their order, height and colour role

## 5. Game-facing code (the riskiest part)

- [ ] **`tg_world`** (525): everything read from the game, namely track types, ground and water, and track ends. It encodes **crash avoidance** (asking the street system about a non-node kills the game, and a proposal naming a missing node kills it). Check that every call goes through the guards.
- [ ] **`tg_gui`** (1857): the React-style GUI plus the tool, probe and menu plugins. By far the biggest file. Its own header lists the parts, so split your reading along those. Read NOTES.md "Tool and GUI" and "GUI pitfalls" first.
  - [ ] imports and types
  - [ ] the menu plugin and its row
  - [ ] the tool (`toolAction`): game callbacks into session events
  - [ ] ghost and proposal handling, build, and the confirm window
  - [ ] gizmo rendering (`EdgeRenderable`) and colours
  - [ ] `TgProbe` (per-frame ground read and badges)
  - [ ] dialogs and windows

## 6. Tests (`test/`, run by `check.sh`)

- [ ] `ends_test` (300), `structures_test`, `crossings_test`

## 7. Cross-cutting checks (do these as you go)

- [ ] Search for Teal's escape hatches: `as any`, `as `, `--@`, and `pcall`. Each one is a place where the type checker was silenced or errors are swallowed.
- [ ] Search for `TODO`, `FIXME` and `HACK`
- [ ] Check magic numbers (thresholds, step sizes, the 40 m minimum radius) against NOTES.md
- [ ] Check that the comments say *why*. Many headers are long, and some may have drifted from the code.
- [ ] Look for dead code and unused exports
- [ ] Look for duplicated logic between `ends`, `edit` and `crossings`
- [ ] Run `./check.sh` yourself and confirm it is green
- [ ] Load the mod in game once and click through a start, an end, an edit and a build
